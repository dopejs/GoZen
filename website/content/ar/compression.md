# ضغط السياق (تجريبي)

:::warning ميزة تجريبية
ضغط السياق ما زال في مرحلة تجريبية. وهو معطّل افتراضيًا ويحتاج إلى إعداد صريح لتفعيله.
:::

يضغط سياق المحادثة تلقائيًا حين يتجاوز عدد الرموز الحد المحدد، فيقلّل التكلفة مع الحفاظ على جودة المحادثة.

## المزايا

- **ضغط تلقائي** — يبدأ عند تجاوز عدد الرموز للحد
- **تلخيص ذكي** — نموذج رخيص (claude-3-haiku) يلخّص الرسائل الأقدم
- **الحفاظ على الرسائل الحديثة** — تبقى الرسائل الأخيرة كما هي للحفاظ على تسلسل السياق
- **تقدير الرموز** — عدّ دقيق قبل استدعاءات الـ API
- **تتبّع الإحصاءات** — راقب فعالية الضغط
- **عمل شفاف** — يعمل بسلاسة مع جميع عملاء الذكاء الاصطناعي

## آلية العمل

1. **تقدير الرموز** — عدّ الرموز في سجل المحادثة
2. **فحص الحد** — المقارنة بالحد المضبوط (الافتراضي: 50,000)
3. **اختيار الرسائل** — تحديد الرسائل الأقدم المرشّحة للضغط
4. **التلخيص** — إنشاء ملخص موجز بنموذج رخيص
5. **استبدال السياق** — استبدال الرسائل القديمة بالملخص
6. **تمرير الطلب** — إرسال السياق المضغوط إلى النموذج الهدف

## الإعداد

### تفعيل الضغط

```json
{
  "compression": {
    "enabled": true,
    "threshold_tokens": 50000,
    "target_tokens": 20000,
    "summarizer_model": "claude-3-haiku-20240307",
    "preserve_recent_messages": 5,
    "tokens_per_char": 0.25
  }
}
```

**الخيارات:**

| الخيار | الافتراضي | الوصف |
|--------|---------|-------------|
| `enabled` | `false` | يفعّل ضغط السياق |
| `threshold_tokens` | `50000` | يبدأ الضغط عند تجاوز السياق لهذا الحد |
| `target_tokens` | `20000` | عدد الرموز المستهدف بعد الضغط |
| `summarizer_model` | `claude-3-haiku-20240307` | النموذج المستخدم في التلخيص |
| `preserve_recent_messages` | `5` | عدد الرسائل الحديثة التي تبقى كما هي |
| `tokens_per_char` | `0.25` | نسبة التقدير عند عدّ الرموز |

### الإعداد لكل ملف تعريف

فعّل الضغط لملفات تعريف بعينها:

```json
{
  "profiles": {
    "long-context": {
      "providers": ["anthropic"],
      "compression": {
        "enabled": true,
        "threshold_tokens": 100000,
        "target_tokens": 40000
      }
    },
    "short-context": {
      "providers": ["openai"],
      "compression": {
        "enabled": false
      }
    }
  }
}
```

## تقدير الرموز

يقدّر GoZen الرموز بسرعة اعتمادًا على عدد المحارف:

```
estimated_tokens = character_count * tokens_per_char
```

**النسبة الافتراضية:** 0.25 رمز لكل محرف (الرمز الواحد ≈ 4 محارف)

**الدقة:** ‏±10% للنص الإنجليزي، وقد تختلف مع لغات أخرى

وللعدّ الدقيق يستخدم GoZen مكتبة `tiktoken-go` عند توفّرها.

## استراتيجية الضغط

### اختيار الرسائل

1. **رسائل النظام** — تُحفظ دائمًا
2. **الرسائل الحديثة** — تُحفظ آخر N رسالة (الافتراضي: 5)
3. **الرسائل الأقدم** — مرشّحة للضغط

### موجّه التلخيص

```
Summarize the following conversation history concisely while preserving key information, decisions, and context:

[older messages]

Provide a brief summary that captures the essential points.
```

### النتيجة

```
Original: 45,000 tokens (30 messages)
After compression: 22,000 tokens (summary + 5 recent messages)
Savings: 23,000 tokens (51%)
```

## واجهة الويب

إعدادات الضغط متاحة على `http://localhost:19840/settings`:

1. انتقل إلى تبويب "Compression" (المؤشَّر بشارة BETA)
2. فعّل "Enable Compression"
3. اضبط الحد وعدد الرموز المستهدف
4. اختر نموذج التلخيص
5. حدّد عدد الرسائل الحديثة التي ستبقى
6. اضغط "Save"

### لوحة الإحصاءات

اطّلع على إحصاءات الضغط:

- **إجمالي عمليات الضغط** — عدد مرات تفعيل الضغط
- **الرموز الموفَّرة** — إجمالي ما تم توفيره
- **متوسط التوفير** — متوسط الانخفاض في الرموز لكل عملية
- **معدّل الضغط** — نسبة الطلبات التي استدعت ضغطًا

## نقاط الـ API

### جلب إحصاءات الضغط

```bash
GET /api/v1/compression/stats
```

الاستجابة:
```json
{
  "enabled": true,
  "total_compressions": 42,
  "tokens_saved": 1250000,
  "average_savings": 29761,
  "compression_rate": 0.15,
  "last_compression": "2026-03-05T10:30:00Z"
}
```

### تحديث إعدادات الضغط

```bash
PUT /api/v1/compression/settings
Content-Type: application/json

{
  "enabled": true,
  "threshold_tokens": 60000,
  "target_tokens": 25000
}
```

### تصفير الإحصاءات

```bash
POST /api/v1/compression/stats/reset
```

## حالات الاستخدام

### جلسات برمجة طويلة

**السيناريو:** جلسة برمجة تمتد ساعات مع Claude Code

**الإعداد:**
```json
{
  "compression": {
    "enabled": true,
    "threshold_tokens": 80000,
    "target_tokens": 30000,
    "preserve_recent_messages": 10
  }
}
```

**الفائدة:** الحفاظ على تسلسل المحادثة دون بلوغ حدود السياق

### المعالجة على دفعات

**السيناريو:** معالجة مستندات كثيرة بالذكاء الاصطناعي

**الإعداد:**
```json
{
  "compression": {
    "enabled": true,
    "threshold_tokens": 40000,
    "target_tokens": 15000,
    "preserve_recent_messages": 3
  }
}
```

**الفائدة:** خفض التكلفة عند معالجة مجموعات مستندات كبيرة

### البحث والتحليل

**السيناريو:** جلسات بحث طويلة تتناول عدة مواضيع

**الإعداد:**
```json
{
  "compression": {
    "enabled": true,
    "threshold_tokens": 100000,
    "target_tokens": 40000,
    "preserve_recent_messages": 8
  }
}
```

**الفائدة:** إبقاء التركيز على المواضيع الحديثة مع الحفاظ على السياق الأسبق

## أفضل الممارسات

1. **ابدأ بالقيم الافتراضية** — تناسب معظم الحالات
2. **راقب الإحصاءات** — تفقّد معدّل الضغط والتوفير بانتظام
3. **اضبط الحد** — ارفعه للنماذج ذات السياق الطويل (Claude Opus)، واخفضه لغيرها
4. **أبقِ رسائل كافية** — احتفظ بـ 5 إلى 10 رسائل حديثة للحفاظ على التسلسل
5. **استخدم نموذج تلخيص رخيصًا** — Haiku سريع وموفّر
6. **اختبر قبل الإنتاج** — تحقّق من جودة الضغط في حالتك تحديدًا

## القيود

1. **فقدان في الجودة** — قد يُفقد التلخيص تفاصيل دقيقة
2. **زيادة الكمون** — يضيف استدعاء API إضافيًا
3. **مفاضلة التكلفة** — تكلفة التلخيص مقابل الرموز الموفَّرة
4. **دعم اللغات** — يعمل أفضل مع الإنجليزية، وقد يختلف مع غيرها
5. **نافذة السياق** — لا يمكن تجاوز النافذة القصوى للنموذج

## معالجة المشكلات

### الضغط لا يبدأ

1. تأكد أن `compression.enabled` مضبوط على `true`
2. تحقّق أن عدد الرموز يتجاوز الحد
3. تأكد أن المحادثة تحتوي على رسائل كافية للضغط
4. راجع سجلات الخدمة بحثًا عن أخطاء الضغط

### جودة تلخيص ضعيفة

1. جرّب نموذج تلخيص آخر (مثل claude-3-sonnet)
2. ارفع `preserve_recent_messages` للاحتفاظ بسياق أكبر
3. ارفع `target_tokens` للسماح بملخصات أطول
4. تحقّق من توفّر نموذج التلخيص وعمله

### ارتفاع الكمون

1. يضيف الضغط استدعاء API واحدًا (التلخيص)
2. استخدم نموذج تلخيص أسرع (Haiku هو الأسرع)
3. ارفع الحد لتقليل تكرار الضغط
4. فكّر في تعطيله في التطبيقات الحساسة للكمون

### تكاليف غير متوقعة

1. راقب تكلفة التلخيص في لوحة الاستخدام
2. قارن التوفير بتكلفة التلخيص
3. ارفع الحد لتقليل تكرار الضغط
4. استخدم أرخص نموذج متاح للتلخيص

## الأثر على الأداء

- **تقدير الرموز** — نحو 1 مللي ثانية لكل طلب (مهمَل)
- **التلخيص** — من 1 إلى 3 ثوانٍ (حسب النموذج وعدد الرسائل)
- **عبء الذاكرة** — ضئيل (نحو 1 كيلوبايت لكل عملية ضغط)
- **توفير التكلفة** — عادةً انخفاض بنسبة 30% إلى 50% في الرموز

## إعدادات متقدمة

### موجّه تلخيص مخصّص

```json
{
  "compression": {
    "enabled": true,
    "custom_prompt": "Create a technical summary of the following conversation, focusing on code changes, decisions, and action items:\n\n{messages}\n\nSummary:"
  }
}
```

### ضغط مشروط

فعّل الضغط في سيناريوهات محددة فقط:

```json
{
  "profiles": {
    "default": {
      "scenarios": {
        "longContext": {
          "providers": ["anthropic"],
          "compression": {
            "enabled": true,
            "threshold_tokens": 100000
          }
        },
        "default": {
          "providers": ["anthropic"],
          "compression": {
            "enabled": false
          }
        }
      }
    }
  }
}
```

### ضغط متعدد المراحل

اضغط أكثر من مرة في المحادثات الطويلة جدًا:

```json
{
  "compression": {
    "enabled": true,
    "stages": [
      {
        "threshold_tokens": 50000,
        "target_tokens": 30000
      },
      {
        "threshold_tokens": 80000,
        "target_tokens": 40000
      }
    ]
  }
}
```

- مقاييس لجودة الضغط وتغذية راجعة
- استراتيجيات ضغط مخصّصة لكل حالة استخدام
- تكامل مع RAG لتخزين السياق خارجيًا
