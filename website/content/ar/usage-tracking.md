# تتبّع الاستخدام وضبط الميزانية

تتبّع استهلاك الرموز والتكاليف عبر المزوّدين والنماذج والمشاريع. وحدِّد سقوف إنفاق تُطبَّق تلقائيًا.

## المزايا

- **تتبّع لحظي** — مراقبة استهلاك الرموز والتكلفة لكل طلب
- **تجميع متعدد الأبعاد** — حسب المزوّد والنموذج والمشروع والفترة الزمنية
- **حدود الميزانية** — سقوف إنفاق يومية وأسبوعية وشهرية
- **إجراءات تلقائية** — التحذير أو خفض النموذج أو حجب الطلبات عند تجاوز الحدود
- **تقدير التكلفة** — تسعير دقيق لجميع النماذج الرئيسية
- **بيانات تاريخية** — تخزين SQLite مع تجميع كل ساعة لتحسين الأداء

## الإعداد

### تفعيل تتبّع الاستخدام

```json
{
  "usage_tracking": {
    "enabled": true,
    "db_path": "~/.zen/usage.db"
  }
}
```

### إعداد تسعير النماذج

```json
{
  "pricing": {
    "models": {
      "claude-opus-4": {
        "input_per_mtok": 15.0,
        "output_per_mtok": 75.0
      },
      "claude-sonnet-4": {
        "input_per_mtok": 3.0,
        "output_per_mtok": 15.0
      },
      "gpt-4o": {
        "input_per_mtok": 2.5,
        "output_per_mtok": 10.0
      }
    },
    "model_families": {
      "claude-opus": {
        "input_per_mtok": 15.0,
        "output_per_mtok": 75.0
      },
      "claude-sonnet": {
        "input_per_mtok": 3.0,
        "output_per_mtok": 15.0
      },
      "gpt-4": {
        "input_per_mtok": 2.5,
        "output_per_mtok": 10.0
      }
    }
  }
}
```

**مطابقة النماذج**: تُطابَق أسماء النماذج الدقيقة أولًا، ثم يُرجَع إلى بادئات عائلة النموذج.

### تحديد حدود الميزانية

```json
{
  "budget": {
    "daily": {
      "enabled": true,
      "limit": 10.0,
      "action": "warn"
    },
    "weekly": {
      "enabled": true,
      "limit": 50.0,
      "action": "downgrade"
    },
    "monthly": {
      "enabled": true,
      "limit": 200.0,
      "action": "block"
    }
  }
}
```

## إجراءات الميزانية

| الإجراء | السلوك |
|---------|--------|
| `warn` | يسجّل تحذيرًا ويرسل إشعار webhook، لكنه يسمح بالطلب |
| `downgrade` | يتحوّل إلى نموذج أرخص (مثل opus ← sonnet ← haiku) |
| `block` | يرفض الطلب برمز الحالة 429 |

## واجهة الويب

لوحة الاستخدام متاحة على `http://localhost:19840/usage`:

- **نظرة عامة** — إجمالي التكلفة والطلبات والرموز للفترة الحالية
- **حسب المزوّد** — تفصيل التكلفة لكل مزوّد
- **حسب النموذج** — إحصاءات الاستخدام لكل نموذج
- **حسب المشروع** — تتبّع التكاليف لكل مشروع (عبر ارتباطات المشاريع)
- **الخط الزمني** — اتجاهات التكلفة بالساعة واليوم
- **حالة الميزانية** — مؤشرات بصرية للحدود اليومية والأسبوعية والشهرية

```bash

  "end": "2026-03-05T23:59:59Z",

  "total_input_tokens": 125000,
  "total_output_tokens": 35000,

    "action": "warn"
  }

```

## التتبّع على مستوى المشروع

تتبّع التكاليف لكل مشروع باستخدام ارتباطات المجلدات:

```bash
# Bind current directory to a profile
zen bind work-profile

# All requests from this directory are tagged with the project path
# View costs in Web UI under "By Project"
```

## إشعارات Webhook

استقبل تنبيهات عند تجاوز الميزانية:

```json
{
  "webhooks": [
    {
      "enabled": true,
      "url": "https://hooks.slack.com/services/YOUR/WEBHOOK/URL",
      "events": ["budget_warning", "budget_exceeded"]
    }
  ]
}
```

راجع [Webhooks](./webhooks.md) للإعداد الكامل.

## أفضل الممارسات

1. **ابدأ بالتحذيرات** — استخدم `warn` في البداية لفهم أنماط الاستخدام
2. **حدّد حدودًا واقعية** — استند إلى بيانات الاستخدام السابقة
3. **استخدم الخفض أثناء التطوير** — انتقل تلقائيًا إلى نماذج أرخص عند الاختبار
4. **احفظ الحجب للإنتاج** — استخدم `block` فقط للسقوف الصارمة
5. **راقب يوميًا** — تفقّد لوحة الاستخدام بانتظام لتجنّب المفاجآت
6. **فعّل الـ webhooks** — احصل على تنبيهات فورية عند الاقتراب من الحدود

## معالجة المشكلات

### الاستخدام لا يُسجَّل

1. تأكد أن `usage_tracking.enabled` مضبوط على `true` في الإعدادات
2. تأكد أن مسار قاعدة البيانات قابل للكتابة: `~/.zen/usage.db`
3. أعد تشغيل الخدمة: `zen daemon restart`

### تكاليف غير صحيحة

1. تأكد أن تسعير النماذج في الإعدادات يطابق الأسعار الحالية
2. تحقّق من مطابقة اسم النموذج (تطابق دقيق مقابل بادئة العائلة)
3. حدّث إعدادات التسعير إذا غيّر المزوّدون أسعارهم

### الميزانية لا تُطبَّق

1. تأكد أن إعداد الميزانية مفعّل
2. تأكد من ضبط الإجراء (`warn` أو `downgrade` أو `block`)
3. راجع سجلات الخدمة بحثًا عن أخطاء في فاحص الميزانية

## الأداء

- **تجميع كل ساعة** — تُجمَّع البيانات الخام كل ساعة لتقليل حِمل الاستعلامات
- **استعلامات مفهرسة** — فهارس على المزوّد والنموذج والمشروع والطابع الزمني
- **تخزين موفّر** — نحو 1 كيلوبايت لكل طلب، ونحو 30 ميغابايت لكل 30,000 طلب
- **لوحة سريعة** — أزمنة استعلام دون الثانية في الاستخدام المعتاد
