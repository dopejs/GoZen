# Инфраструктура агентов (БЕТА)

:::warning Функция в стадии БЕТА
Инфраструктура агентов находится в бете. По умолчанию она выключена и требует явной настройки.
:::

Встроенная поддержка автономных агентных сценариев: управление сессиями, координация файлов, наблюдение в реальном времени и защитные ограничения.

## Возможности

- **Среда выполнения агентов** — запуск автономных задач с полным управлением жизненным циклом
- **Обсерватория** — наблюдение за сессиями и активностью агентов в реальном времени
- **Ограничения** — правила безопасности и рамки поведения агентов
- **Координатор** — координация через файлы для сценариев с несколькими агентами
- **Очередь задач** — управление задачами с приоритетами и зависимостями
- **Управление сессиями** — отслеживание сессий агентов в нескольких проектах

## Архитектура

```
Agent Client (Claude Code, Codex, etc.)
    ↓
Agent Runtime
    ↓
┌─────────────┬──────────────┬─────────────┐
│ Observatory │ Guardrails   │ Coordinator │
│ (Monitor)   │ (Safety)     │ (Sync)      │
└─────────────┴──────────────┴─────────────┘
    ↓
Task Queue → Provider API
```

## Компоненты

### 1. Среда выполнения агентов

Управляет жизненным циклом выполнения агентных задач.

**Возможности:**
- Планирование и выполнение задач
- Управление параллельными задачами
- Обработка тайм-аутов
- Автоматическая очистка
- Восстановление после ошибок

**Настройка:**
```json
{
  "runtime": {
    "max_concurrent_tasks": 5,
    "task_timeout": "30m",
    "auto_cleanup": true,
    "retry_failed_tasks": true,
    "max_retries": 3
  }
}
```

**API:**
```bash
# Start agent task
POST /api/v1/agent/tasks
Content-Type: application/json

{
  "name": "code-review",
  "description": "Review pull request #123",
  "priority": 1,
  "config": {
    "model": "claude-opus-4",
    "max_tokens": 100000
  }
}

# Get task status
GET /api/v1/agent/tasks/{task_id}

# Cancel task
DELETE /api/v1/agent/tasks/{task_id}
```

### 2. Обсерватория

Наблюдение за активностью агентов в реальном времени.

**Возможности:**
- Отслеживание сессий
- Журнал активности
- Метрики производительности
- Обновления состояния
- Исторические данные

**Настройка:**
```json
{
  "observatory": {
    "enabled": true,
    "update_interval": "5s",
    "history_retention": "7d",
    "metrics": {
      "track_tokens": true,
      "track_costs": true,
      "track_latency": true
    }
  }
}
```

**Отслеживаемые метрики:**
- Активные сессии
- Задачи в работе
- Расход токенов
- Вызовы API
- Файловые операции
- Доля ошибок
- Средняя задержка

**API:**
```bash
# Get all active sessions
GET /api/v1/agent/sessions

# Get session details
GET /api/v1/agent/sessions/{session_id}

# Get session metrics
GET /api/v1/agent/sessions/{session_id}/metrics
```

### 3. Ограничения

Правила безопасности и рамки поведения агентов.

**Возможности:**
- Лимиты на операции
- Ограничения по путям
- Блокировка команд
- Квоты ресурсов
- Процедуры подтверждения

**Настройка:**
```json
{
  "guardrails": {
    "enabled": true,
    "max_file_operations": 100,
    "max_api_calls": 1000,
    "max_tokens_per_session": 1000000,
    "allowed_paths": [
      "/Users/john/projects",
      "/tmp/agent-workspace"
    ],
    "blocked_paths": [
      "/etc",
      "/System",
      "~/.ssh"
    ],
    "blocked_commands": [
      "rm -rf /",
      "sudo",
      "chmod 777"
    ],
    "require_approval": {
      "file_delete": true,
      "system_commands": true,
      "network_requests": false
    }
  }
}
```

**Как применяются:**
- Проверка до выполнения
- Наблюдение в реальном времени
- Автоматическая блокировка
- Запросы на подтверждение
- Журнал аудита

**API:**
```bash
# Get guardrail status
GET /api/v1/agent/guardrails

# Update guardrail rules
PUT /api/v1/agent/guardrails
Content-Type: application/json

{
  "max_file_operations": 200,
  "blocked_commands": ["rm -rf", "sudo", "dd"]
}
```

### 4. Координатор

Координация через файлы для сценариев с несколькими агентами.

**Возможности:**
- Блокировки файлов
- Обнаружение изменений
- Разрешение конфликтов
- Синхронизация состояния
- Уведомления о событиях

**Настройка:**
```json
{
  "coordinator": {
    "enabled": true,
    "lock_timeout": "5m",
    "change_detection": true,
    "conflict_resolution": "last-write-wins",
    "notification_webhook": "https://hooks.slack.com/..."
  }
}
```

**Сценарии:**
- Несколько агентов правят одни и те же файлы
- Предотвращение одновременных изменений
- Обнаружение внешних изменений файлов
- Координация агентных сценариев

**API:**
```bash
# Acquire file lock
POST /api/v1/agent/locks
Content-Type: application/json

{
  "path": "/path/to/file.go",
  "session_id": "sess_123",
  "timeout": "5m"
}

# Release file lock
DELETE /api/v1/agent/locks/{lock_id}

# Get file change events
GET /api/v1/agent/changes?since=2026-03-05T10:00:00Z
```

### 5. Очередь задач

Управляет задачами агентов с приоритетами и зависимостями.

**Возможности:**
- Планирование по приоритету
- Зависимости между задачами
- Управление очередью
- Отслеживание состояния
- Логика повторов

**Настройка:**
```json
{
  "task_queue": {
    "enabled": true,
    "max_queue_size": 100,
    "priority_levels": 5,
    "enable_dependencies": true,
    "retry_policy": {
      "max_retries": 3,
      "backoff": "exponential"
    }
  }
}
```

**API:**
```bash
# Add task to queue
POST /api/v1/agent/queue
Content-Type: application/json

{
  "name": "run-tests",
  "priority": 2,
  "depends_on": ["build-project"],
  "config": {}
}

# Get queue status
GET /api/v1/agent/queue

# Remove task from queue
DELETE /api/v1/agent/queue/{task_id}
```

## Веб-интерфейс

Панель агентов доступна по адресу `http://localhost:19840/agent`:

### Вкладка «Sessions»

- **Активные сессии** — сессии агентов, работающие сейчас
- **Детали сессии** — прогресс задач, метрики, журналы
- **Управление сессией** — пауза, продолжение, отмена

### Вкладка «Tasks»

- **Очередь задач** — ожидающие и выполняющиеся задачи
- **История задач** — завершённые и неудавшиеся
- **Детали задачи** — конфигурация, журналы, результаты

### Вкладка «Guardrails»

- **Лимиты операций** — текущий расход относительно лимитов
- **Заблокированные операции** — недавние блокировки
- **Очередь подтверждений** — операции, ожидающие подтверждения

### Вкладка «Metrics»

- **Расход токенов** — по сессиям и суммарно
- **Вызовы API** — количество и частота запросов
- **Файловые операции** — чтения, записи, удаления
- **Производительность** — задержка и пропускная способность

## Интеграция с Claude Code

GoZen автоматически распознаёт сессии Claude Code и предоставляет им инфраструктуру агентов:

```bash
# Start Claude Code with agent support
zen --agent

# Agent features are automatically enabled:
# - Session tracking
# - File coordination
# - Guardrails enforcement
# - Real-time monitoring
```

**Польза:**
- Предотвращение одновременных правок файлов
- Учёт расхода токенов и стоимости
- Применение ограничений безопасности
- Наблюдение за активностью агентов
- Координация сценариев с несколькими агентами

## Сценарии использования

### Разработка несколькими агентами

Несколько агентов работают над одной кодовой базой:

```json
{
  "agent": {
    "coordinator": {
      "enabled": true,
      "lock_timeout": "5m",
      "change_detection": true
    },
    "guardrails": {
      "max_file_operations": 200,
      "allowed_paths": ["/Users/john/project"]
    }
  }
}
```

### Долгие задачи

Наблюдайте и управляйтедлительными задачами агентов:

```json
{
  "agent": {
    "runtime": {
      "task_timeout": "2h",
      "auto_cleanup": false
    },
    "observatory": {
      "update_interval": "10s",
      "history_retention": "30d"
    }
  }
}
```

### Критичные для безопасности операции

Применяйте строгие ограничения:

```json
{
  "agent": {

      "enabled": true,
      "max_file_operations": 50,
      "blocked_commands": ["rm", "sudo", "chmod"],
      "require_approval": {
        "file_delete": true,
        "system_commands": true,
        "network_requests": true

  }

```

## Рекомендации

1. **Включайте ограничения** — всегда в боевой среде
2. **Задавайте разумные лимиты** — настраивайте под свой сценарий
3. **Наблюдайтеактивно** — регулярно смотрите панель обсерватории
4. **Используйте блокировки файлов** — включайте координатор для сценариев с несколькими агентами
5. **Настройте подтверждения** — требуйте подтверждения для разрушительных операций
6. **Просматривайте журналы** — регулярно проверяйте активность агентов

## Ограничения

1. **Накладные расходы** — наблюдение и координация добавляют задержку
2. **Блокировки файлов** — могут замедлять работу нескольких агентов
3. **Расход памяти** — история сессий занимает память
4. **Сложность** — требует понимания агентных сценариев
5. **Статус беты** — возможности могут измениться

## Устранение неполадок

### Сессия агента не отслеживается

1. Убедитесь, что `agent.enabled` равно `true`
2. Проверьте, что обсерватория включена
3. Убедитесь, что клиент агента поддерживается (Claude Code, Codex)
4. Изучите журналы демона

### Проблемы с блокировками файлов

1. Проверьте, что координатор включён
2. Убедитесь, что тайм-аут блокировки подходит
3. Посмотрите активные блокировки: `GET /api/v1/agent/locks`
4. При необходимости снимите зависшие блокировки вручную

### Ограничения не применяются

1. Проверьте, что они включены
2. Проверьте конфигурацию правил
3. Просмотрите журнал заблокированных операций
4. Убедитесь, что клиент агента соблюдает ограничения

### Высокий расход памяти

1. Сократите срок хранения истории
2. Увеличьте интервал обновления
3. Ограничьте число параллельных задач
4. Включите автоматическую очистку

## Вопросы безопасности

1. **Ограничения по путям** — всегда задавайте разрешённые и запрещённые пути
2. **Блокировка команд** — блокируйте опасные команды
3. **Процедуры подтверждения** — требуйте подтверждения для чувствительных операций
4. **Журнал аудита** — включите полное журналирование
5. **Лимиты ресурсов** — задайте разумные лимиты операций
