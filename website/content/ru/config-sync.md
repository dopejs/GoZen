# Синхронизация конфигурации

Синхронизируйте провайдеров, профили, профиль по умолчанию и клиент по умолчанию между устройствами. Токены авторизации шифруются с помощью AES-256-GCM (выведение ключа PBKDF2-SHA256) до отправки.

## Поддерживаемые хранилища

| Хранилище | Описание |
|-----------|----------|
| `webdav` | Любой сервер WebDAV (например, Nextcloud, ownCloud) |
| `s3` | AWS S3 или S3-совместимое хранилище (например, MinIO, Cloudflare R2) |
| `gist` | Приватный gist (нужен PAT с областью gist) |
| `repo` | Файл в репозитории через Contents API (нужен PAT с областью repo) |

## Настройка

Настройте синхронизацию на странице настроек веб-интерфейса:

```bash
# Открыть настройки веб-интерфейса
zen web  # Настройки → Синхронизация конфигурации
```

Либо получите данные вручную через CLI:

```bash
zen config sync
```

## Пример конфигурации

```json
{
  "sync": {
    "backend": "gist",
    "gist_id": "abc123def456",
    "token": "ghp_xxxxxxxxxxxx",
    "passphrase": "my-secret-passphrase",
    "auto_pull": true,
    "pull_interval": 300
  }
}
```

## Шифрование

Если задана парольная фраза, все токены авторизации в передаваемых данных шифруются AES-256-GCM ключом, выведенным через PBKDF2-SHA256 (600 000 итераций). Соль хранится рядом с данными. Без парольной фразы данные выгружаются открытым JSON.

## Разрешение конфликтов

- Слияние по временным меткам для каждой сущности: побеждает более позднее изменение
- Для удалённых сущностей используются «надгробия» (истекают через 30 дней)
- Скалярные значения (профиль/клиент по умолчанию): побеждает более поздняя метка

## Что синхронизируется

**Синхронизируется:** провайдеры (с зашифрованными токенами), профили, профиль по умолчанию, клиент по умолчанию

**Не синхронизируется:** настройки портов, пароль веб-интерфейса, привязки проектов, сама конфигурация синхронизации
