# Балансировка нагрузки

Кроме обычного переключения при отказе, GoZen поддерживает несколько стратегий выбора провайдера. Стратегия задаётся для каждого профиля, сочетается с проверками здоровья и направляет трафик по доступности, задержке или стоимости.

## Доступные стратегии

### Переключение при отказе

Провайдеры перебираются по порядку, пока один не ответит. Это стратегия по умолчанию, удобная для схемы «основной/резервный».

```json
{
  "profiles": {
    "default": {
      "providers": ["primary", "backup"],
      "strategy": "failover"
    }
  }
}
```

### Круговой перебор

Равномерно распределяет запросы между несколькими равнозначными провайдерами.

```json
{
  "profiles": {
    "balanced": {
      "providers": ["provider-a", "provider-b", "provider-c"],
      "strategy": "round-robin"
    }
  }
}
```

### Наименьшая задержка

Предпочитает провайдера с наименьшим недавним временем ответа.

```json
{
  "profiles": {
    "fast": {
      "providers": ["us-east", "us-west", "eu"],
      "strategy": "least-latency"
    }
  }
}
```

### Наименьшая стоимость

Предпочитает самого дешёвого провайдера для запрошенной модели.

```json
{
  "profiles": {
    "budget": {
      "providers": ["cheap-provider", "premium-provider"],
      "strategy": "least-cost"
    }
  }
}
```

## Маршрутизация с учётом здоровья

Все стратегии работают вместе с мониторингом здоровья. Когда включён `health_aware`, нездоровые провайдеры автоматически пропускаются до восстановления.

```json
{
  "profiles": {
    "production": {
      "providers": ["primary", "secondary", "tertiary"],
      "strategy": "least-latency",
      "health_aware": true
    }
  }
}
```

## Как выбрать стратегию

- Берите `failover`, когда важнее всего надёжность.
- Берите `round-robin`, когда провайдеры взаимозаменяемы.
- Берите `least-latency` для интерактивных и чувствительных ко времени задач.
- Берите `least-cost`, когда бюджет важнее скорости.
