# Учёт использования и контроль бюджета

Отслеживайте расход токенов и стоимость по провайдерам, моделям и проектам. Задавайте лимиты расходов с автоматическим применением мер.

## Возможности

- **Учёт в реальном времени** — расход токенов и стоимость по каждому запросу
- **Многомерная агрегация** — по провайдеру, модели, проекту и периоду
- **Лимиты бюджета** — дневные, недельные и месячные потолки расходов
- **Автоматические действия** — предупредить, понизить модель или заблокировать запрос при превышении
- **Оценка стоимости** — точные тарифы для всех основных моделей
- **Исторические данные** — хранилище SQLite с почасовой агрегацией для скорости

## Настройка

### Включение учёта

```json
{
  "usage_tracking": {
    "enabled": true,
    "db_path": "~/.zen/usage.db"
  }
}
```

### Настройка тарифов моделей

```json
{
  "pricing": {
    "models": {
      "claude-opus-4": {
        "input_per_mtok": 15.0,
        "output_per_mtok": 75.0
      },
      "claude-sonnet-4": {
        "input_per_mtok": 3.0,
        "output_per_mtok": 15.0
      },
      "gpt-4o": {
        "input_per_mtok": 2.5,
        "output_per_mtok": 10.0
      }
    },
    "model_families": {
      "claude-opus": {
        "input_per_mtok": 15.0,
        "output_per_mtok": 75.0
      },
      "claude-sonnet": {
        "input_per_mtok": 3.0,
        "output_per_mtok": 15.0
      },
      "gpt-4": {
        "input_per_mtok": 2.5,
        "output_per_mtok": 10.0
      }
    }
  }
}
```

**Сопоставление моделей**: сначала сверяются точные имена моделей, затем — префиксы семейства.

### Установка лимитов бюджета

```json
{
  "budget": {
    "daily": {
      "enabled": true,
      "limit": 10.0,
      "action": "warn"
    },
    "weekly": {
      "enabled": true,
      "limit": 50.0,
      "action": "downgrade"
    },
    "monthly": {
      "enabled": true,
      "limit": 200.0,
      "action": "block"
    }
  }
}
```

## Действия при превышении бюджета

| Действие | Поведение |
|----------|-----------|
| `warn` | Пишет предупреждение в журнал и отправляет webhook, но пропускает запрос |
| `downgrade` | Переключает на более дешёвую модель (например, opus → sonnet → haiku) |
| `block` | Отклоняет запрос с кодом 429 |

## Веб-интерфейс

Панель использования доступна по адресу `http://localhost:19840/usage`:

- **Обзор** — суммарная стоимость, запросы и токены за текущий период
- **По провайдерам** — разбивка стоимости по провайдерам
- **По моделям** — статистика использования по моделям
- **По проектам** — расходы по проектам (через привязки каталогов)
- **Хронология** — почасовые и дневные тренды расходов
- **Состояние бюджета** — наглядные индикаторы дневных, недельных и месячных лимитов


### Обновить лимиты бюджета

```bash
PUT /api/v1/budget/limits
Content-Type: application/json

{
  "daily": {
    "enabled": true,
    "limit": 15.0,
    "action": "warn"
  }
}
```

## Учёт на уровне проекта

Отслеживайте расходы по проектам через привязки каталогов:

```bash
# Bind current directory to a profile
zen bind work-profile

# All requests from this directory are tagged with the project path
# View costs in Web UI under "By Project"
```

## Уведомления через webhook

Получайте оповещения при превышении бюджета:

```json
{
  "webhooks": [
    {
      "enabled": true,
      "url": "https://hooks.slack.com/services/YOUR/WEBHOOK/URL",
      "events": ["budget_warning", "budget_exceeded"]
    }
  ]
}
```

Полная настройка описана в разделе [Webhooks](./webhooks.md).

## Рекомендации

1. **Начните с предупреждений** — сперва используйте `warn`, чтобы понять характер расходов
2. **Ставьте реалистичные лимиты** — опирайтесь на историю потребления
3. **Понижение модели для разработки** — при тестах автоматически переходите на более дешёвые модели
4. **Блокировку — для продакшена** — применяйте `block` только для жёстких потолков расходов
5. **Смотрите ежедневно** — регулярно проверяйте панель, чтобы не было сюрпризов
6. **Включите webhooks** — получайте оповещения при приближении к лимиту

## Устранение неполадок

### Использование не учитывается

1. Убедитесь, что в конфигурации `usage_tracking.enabled` равно `true`
2. Проверьте, что путь к базе доступен для записи: `~/.zen/usage.db`
3. Перезапустите демон: `zen daemon restart`

### Неверная стоимость

1. Проверьте, что тарифы моделей в конфигурации соответствуют актуальным
2. Проверьте сопоставление имени модели (точное совпадение или префикс семейства)
3. Обновите тарифы, если провайдер изменил цены

### Бюджет не применяется

1. Проверьте, что настройка бюджета включена
2. Убедитесь, что задано действие (`warn`, `downgrade` или `block`)
3. Просмотрите журналы демона на предмет ошибок проверки бюджета

## Производительность

- **Почасовая агрегация** — сырые данные сводятся раз в час, что снижает нагрузку на запросы
- **Индексы** — индексы по провайдеру, модели, проекту и времени
- **Экономное хранение** — около 1 КБ на запрос, около 30 МБ на 30 000 запросов
- **Быстрая панель** — время запроса меньше секунды при обычных объёмах
